= OpenShift Application Management
:page-toclevels: 1

Learn the application lifecycle on OpenShift by deploying and operating WeatherNow, a web application. This lab covers deployment, inspection, TLS routes, scaling, self-healing, health checks, rollback, and PodDisruptionBudgets.

**Duration:** Approximately 30 minutes, including setup and cleanup +
**Audience:** Platform engineers and operations teams +
**Prerequisites:** A provisioned OpenShift cluster, the supplied administrator credentials, and basic familiarity with shell commands.

== Your Lab Workspace

The instructions appear on the left. Use the tabs on the right to work with your cluster, and drag the divider to resize the panels.

[cols="1,3",options="header"]
|===
|Tab |Purpose

|**OCP Console**
|Deploy WeatherNow and inspect workloads in the OpenShift web console.

|**Terminal**
|Run the lab's `oc` commands in the supplied browser terminal.

|**Terminal 2**
|Keep a second terminal available to watch pods while running commands in the first.
|===

TIP: Use the execute button on command blocks to send commands to the primary **Terminal** tab. Run watch commands manually in **Terminal 2** so the primary terminal remains available.

== Verify Terminal Access

Open **Terminal** and check that the OpenShift CLI is authenticated:

[source,bash,role="execute"]
----
oc whoami
oc whoami --show-server
oc get nodes
----

Confirm that the user and API server belong to your lab environment and that the nodes show `Ready`. The number of nodes depends on your environment.

If `oc whoami` reports that you are not logged in, open the user menu in the console, select **Copy login command**, and follow the prompts. Paste the supplied `oc login` command into **Terminal**, then repeat the checks above. Verify `oc whoami` in **Terminal 2** as well before using it.

The lab creates its resources in the `app-management` project. The PodDisruptionBudget exercise also uses administrator access to demonstrate a blocked node drain on the supplied lab cluster.
