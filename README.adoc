= OpenShift Application Management

A standalone Showroom lab for deploying and operating WeatherNow on OpenShift. The lab covers deployment, inspection, TLS routes, scaling, self-healing, probes, rollback, PodDisruptionBudgets, and cleanup.

== Lab Content

* link:content/modules/ROOT/pages/index.adoc[Lab Setup] — workspace tabs, console login, and CLI access checks.
* link:content/modules/ROOT/pages/02-app-mgmt.adoc[Application Management] — the complete hands-on lab and wrap-up.

Allow approximately 30 minutes. Navigation is always visible; no module selection flags are required. All required screenshots and diagrams are under `content/modules/ROOT/assets/images/`. The exercises create resources inline, so no separate application manifests or setup scripts are needed.

== Showroom Deployment

Use this repository as the Showroom content source:

[source,yaml]
----
content:
  repoUrl: https://github.com/rhpds/zt-ocp-ops-app-management.git
  repoRef: main
  antoraPlaybook: default-site.yml
----

The Antora component is `zt-ocp-ops-app-management`, version `main`. Both playbooks and link:ui-config.yml[ui-config.yml] use that identity.

Provision a lab OpenShift cluster with administrator access, a Wetty terminal with the `oc` CLI, and console embedding enabled. The cluster must be able to pull the WeatherNow image from Quay and the rollback exercise image from the Red Hat registry. This content repository does not provision the cluster or terminal service.

Supply these Antora attributes through Showroom `user_data`:

* `openshift_cluster_console_url`
* `openshift_cluster_admin_username`
* `openshift_cluster_admin_password`

The workspace has three tabs: *OCP Console*, *Terminal*, and *Terminal 2*. Both terminal tabs connect to `/wetty` over port `443`. The second terminal is available for watching pod changes. The UI retains split view, resizing, persistent URL state, and the theme's command execution controls.

Showroom replaces `${DOMAIN}` in the console tab URL with the cluster apps domain. See the link:https://rhpds.github.io/showroom_template_nookbag/modules/ui-config.html[Showroom UI configuration documentation] for deployment details.

=== Compatibility Hook

Deployers that invoke link:.workshop/inject-env-vars.sh[inject-env-vars.sh] can continue to do so. The hook merges nonempty `MASTER_URL`, `ADMIN_USERNAME` (or `ADMIN_USER`), and `ADMIN_PASSWORD` values into the playbook. It can derive the console URL from `ROUTE_SUBDOMAIN` or `DOMAIN`. When a legacy admin password is supplied without a username, the username defaults to `admin`.

Existing attributes are preserved when corresponding environment values are absent. The hook resolves the console URL in the existing UI configuration and preserves both terminal tabs. It ignores legacy module flags and does not print credentials.

The default paths are `/showroom/repo` and `/showroom/www`; `SHOWROOM_REPO_DIR` and `SHOWROOM_WWW_DIR` override them for testing or alternate deployments.

== Local Preview

Build and serve the instructions with Antora and Podman:

[source,sh]
----
./local-build/up.sh
----

Open http://localhost:8080/index.html.

[cols="1,2"]
|===
| `./local-build/build.sh` | Build the static site in `www/` using `site.yml`.
| `./local-build/serve.sh` | Serve `www/` on port 8080 with Podman.
| `./local-build/stop.sh` | Stop the preview server.
| `./local-build/reset.sh` | Stop, rebuild, and serve again.
| `./local-build/status.sh` | Show preview container status.
|===

Set `SHOWROOM_PORT` to change the port, or `SHOWROOM_SITE_YML` to choose an alternate playbook. To build directly with Antora 3.1:

[source,sh]
----
antora generate site.yml --stacktrace
----

A static preview renders the instructions and images. Live tabs, terminals, credentials, and command execution require the deployed Showroom services and its outer UI.

== Theme and Publishing

Both playbooks use the link:https://github.com/dialvare/rhdp_showroom_theme/releases/tag/v2.0.4-ops[RHDP Showroom theme, v2.0.4-ops], retaining support for command blocks with `role="execute"`.

The GitHub Pages workflow builds `site.yml` and publishes `www/`. When Pages is enabled for this repository, the instructions are available at https://rhpds.github.io/zt-ocp-ops-app-management/.
